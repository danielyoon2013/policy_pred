# Benchmark cells (Phase 2/3 of the matrix-experiments plan)

Eight YAMLs covering 4 (backend, benchmark) cells × {base-only control,
LoRA-SFT trained}. Each cell answers: does `base + LoRA-SFT on the
matching generator-A/C data` meaningfully improve over base alone?

| File | Backend | Benchmark | Adapter |
|---|---|---|---|
| `talkie_arc.yaml` | Talkie 13B | ARC-Challenge | LoRA-SFT on Gen A |
| `talkie_arc_base.yaml` | Talkie 13B | ARC-Challenge | none (control) |
| `talkie_gsm8k.yaml` | Talkie 13B | GSM8K MC | LoRA-SFT on Gen C |
| `talkie_gsm8k_base.yaml` | Talkie 13B | GSM8K MC | none (control) |
| `nanochat_arc.yaml` | nanochat 1.36B | ARC-Challenge | LoRA-SFT on Gen A |
| `nanochat_arc_base.yaml` | nanochat 1.36B | ARC-Challenge | none (control) |
| `nanochat_gsm8k.yaml` | nanochat 1.36B | GSM8K MC | LoRA-SFT on Gen C |
| `nanochat_gsm8k_base.yaml` | nanochat 1.36B | GSM8K MC | none (control) |

## Order of operations

1. **Base-only controls** (4 evals, ~10 min total — they just probe each
   backend on each benchmark with no adapter):
   ```bash
   for yaml in talkie_arc_base talkie_gsm8k_base nanochat_arc_base nanochat_gsm8k_base; do
       python eval.py --experiment experiments/benchmark/${yaml}.yaml --no-adapter --force
   done
   ```
2. **Train 4 LoRA-SFT adapters** (each ~30 min on 4× H100, ~2 hr on 4× A100):
   ```bash
   for yaml in talkie_arc talkie_gsm8k nanochat_arc nanochat_gsm8k; do
       accelerate launch --num_processes=4 --mixed_precision=no \
           train.py --experiment experiments/benchmark/${yaml}.yaml --sft
   done
   ```
3. **Eval the 4 trained adapters** (1 min each):
   ```bash
   for yaml in talkie_arc talkie_gsm8k nanochat_arc nanochat_gsm8k; do
       python eval.py --experiment experiments/benchmark/${yaml}.yaml --force
   done
   ```
4. **Decision gate**: compare base-only vs +LoRA-SFT for each cell. If
   the SFT score doesn't meaningfully exceed the base score, the
   training pipeline is broken — STOP and debug before spending Phase 4
   compute on the policy chain.

## Notes

- The same `arc_mc` / `gsm_mc` evaluators in `evaluators/` are used for
  base-only and trained runs. `--no-adapter` controls whether the adapter
  is loaded.
- `--sft` on the train.py invocation enables prompt-masking loss
  (assistant tokens only). The training data is in
  `{"messages": [user, assistant]}` chat format — `render_chat_record`
  in train.py handles the split.
- For the policy column we use a different SFT data file
  (`data_links/sft/format_sft.jsonl`, generated by
  `synth/sft_format/run.py`). The benchmark cells deliberately use the
  benchmark-matched generator data instead, since the goal there is to
  probe whether the model can answer benchmark-style questions, not
  yes/no/likert.
